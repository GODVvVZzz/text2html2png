# Narrative — 叙事长图 / 产品说明图文版

PRD 图文版、方案说明、立项 brief、项目复盘、评审材料——当用户要的不是"一张图",而是"一份讲清楚来龙去脉的图文说明"时,用这个类型。

内容与结构均为合成示例。断言与叙述须来自用户素材;未拍板的细节按 SKILL.md 的推断规则直接给出最合理的取值。

---

## Layout

```
[Title]
┌──────────────────────────────────────┐
│ 01  🧩  结论先行                       │
│ ┌────────┐ ┌────────┐ ┌────────┐     │
│ │01 · R1 │ │02 · R2 │ │03 · R3 │     │
│ └────────┘ └────────┘ └────────┘     │
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│ 02  🚀  发布管线                       │
│ [提交] → [审核] → [签名] → [发布]      │
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│ 03  🧾  影响面（表格）                  │
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│ 04  ⚠️  风险与依赖（callout）           │
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│ 05  ✅  验收标准（✓ 清单）              │
│ 06  🚫  非目标（✕ 清单）               │
└──────────────────────────────────────┘
[Footer]
```

纵向长画布,每节一张卡:节号 + 图标槽(emoji/SVG 双通道) + eyebrow + 标题,下接该节的模块。

---

## Section modules

| kind | 用途 | 数量约束 |
|---|---|---|
| `cards` | 编号决策/需求/结论卡 | 3–6 张,3 列网格自动排布 |
| `steps` | 横向步骤条,箭头连接 | 3–5 步,每步 ≤18 字符标签 |
| `table` | 影响面/术语/对比表 | 2–3 列,3–6 行 |
| `callout` | 风险、依赖、关键提示 | 单段文本,`info`/`warn` 两种语气 |
| `checklist` | 验收标准(✓)或非目标(✕) | 3–6 项,双列网格 |

一页 4–7 节,节号按 fixture 顺序自动生成(01、02、…)。每节必须有 eyebrow(≤24 字符)和标题。

## Narrative shape

推荐"决策先行"骨架,但顺序服从素材:

1. **结论/决策** — cards,把最重要的事放在第一屏
2. **过程/管线** — steps
3. **影响/对照** — table
4. **风险/依赖** — callout
5. **边界与验收** — checklist(非目标用 `ok: false`)

## Style

默认 `warm`(亲和、汇报感)或 `glass`(现代、产品感)。emoji 槽在 warm/glass/neon/dark 下显示,与主题的图标语言保持一致。

## Guardrails

- 每节一个模块,不要在同一节里堆叠两种模块。
- 卡片正文 ≤ 两行;出现孤字行就缩短文案。
- 表格单元格不换行超过两行;过长就拆行或精简。
- checklist 的标记(✓/✕)与文本语义一致;非目标节用 ✕。
- callout 不再重复节标题,只写正文。
