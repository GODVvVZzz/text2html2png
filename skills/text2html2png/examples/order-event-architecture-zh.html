订单事件架构：同步受理，异步协作

层间箭头仅表示分组层级；具体依赖、事件方向与数据归属以节点文字为准。

入口

商城前端

同步调用订单服务，创建订单。

支付平台

携带回调 ID，同步调用回调服务。

分组层级 · 非节点连线
服务

订单状态维护与可靠事件发布

订单服务：写订单库，异步发布 OrderCreated；消费 PaymentConfirmed，在同一事务更新支付状态与已消费事件 ID。

支付回调幂等处理与事件发布

回调服务：写回调库，事务提交后确认接收；按回调 ID 去重，异步发布 PaymentConfirmed。

库存预留与重复事件去重

库存消费者：异步消费 OrderCreated，在同一事务写入库存预留结果与已消费事件 ID。

分组层级 · 非节点连线
资源

订单库

PostgreSQL；仅订单服务读写。订单与 outbox 同一事务提交；保存消费去重记录。

回调库

独立 PostgreSQL；仅回调服务读写。回调 ID 与 outbox 同一事务提交。

库存库

独立 PostgreSQL；仅库存消费者读写。保存预留结果和消费去重记录。

业务事件队列

至少一次投递。OrderCreated → 库存消费者；PaymentConfirmed → 订单服务。

可靠性边界

订单与回调服务各自从 outbox 重试失败发布。回调按回调 ID 去重；订单与库存消费按事件 ID 去重。至少一次投递不等于恰好一次处理；图中没有逐节点连线或串行调用链。
