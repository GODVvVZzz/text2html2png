Product brief · plugins

Plugin marketplace revamp

One structured entry for skills, experts, and expert teams. This brief leads with the decisions, then scope, impact, and acceptance.

01 🧩

Decision-first

The revamp in six decisions

01 · R1

One template structure

The registry keeps a single skill structure; user uploads and official listings share it.

02 · R2

Teams get uploads

Compose a team prompt from marketplace experts and name one member as leader.

03 · R3

Fixed creation order

Skill first, then expert, then team; the order never reverses.

04 · R4

Signed listings

Every published plugin is content-signed at review time.

05 · R5

One-click rollback

Any release can roll back to the last signed version in one click.

06 · R6

Usage analytics

Authors see installs, retention, and failure counts per version.

02 🚀

Pipeline

How a listing goes live

  1. 📦

    Submit

    Author uploads the manifest and bundle.

  2. 👀

    Review

    Automated checks plus a human pass.

  3. 🔒

    Sign

    The signing service pins content hashes.

  4. 🚀

    Publish

    Listing appears with its signature.

03 🧾

Impact

What changes for whom

AudienceTodayAfter the revamp
AuthorsRe-upload the full bundle per releaseSigned delta updates per version
UsersSearch by name onlySearch by capability and version
ReviewersManual checklists per releaseSigned manifests with a one-click diff
SupportReproduce from screenshotsEvery ticket pins version and platform
04 ⚠️

Dependency

Risks and dependencies

The signing service ships two weeks before the marketplace cutover. If the key-management integration slips, R4 falls back to hash pinning and keeps the release date.

05 ✅

Acceptance

Definition of done

  • A new author publishes a signed plugin without leaving the wizard
  • Rollback restores the previous signed version in under a minute
  • Search returns a plugin by capability, not only by name
  • Every ticket template pins the plugin version and platform
06 🚫

Boundary

Non-goals for this revamp

  • ✕Monetization and revenue sharing
  • ✕Cross-marketplace federation
  • ✕Mobile client parity
  • ✕Migrating legacy v1 manifests
Decision owners

R1–R3 product, R4–R5 platform, R6 growth. Security sign-off is required before R4 enters build. All names and figures are synthetic sample data.
