Open-source roadmap

Six milestones to a plugin API

A public plan for the charting library, first render to extensible core, 2031–2033.

2031 Q2
📈

v0.1 First render

Line and bar marks draw from a plain array of numbers. One canvas target, no interaction, no theming.

2031 Q4
📐

v0.4 Scales and axes

Linear, time, and ordinal scales, with tick labels chosen from the data range instead of hard-coded.

2032 Q1
🖱️

v0.7 Interaction layer

Hover, tooltip, and range selection, each reachable from the keyboard and announced to screen readers.

2032 Q3
🔒

v1.0 Stable API

Semantic versioning begins. The mark, scale, and theme contracts are frozen for the whole 1.x line.

2033 Q1
📄

v1.4 Server rendering

The same chart definition renders to static SVG without a browser, for documents and email digests.

2033 Q3
🧩

v2.0 Plugin API

Marks, scales, and themes can ship as separate packages, so the core stops growing with every new chart.

Roadmap note

Quarters are targets, not commitments. Scope moves before a date does, and every milestone ships from main.
