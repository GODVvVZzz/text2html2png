# Repository content boundary

Keep product source, portable skills, tests, installation and contributor docs,
reproducible quality evidence, public product examples, and generic brand assets
in the open-source repository.

Keep maintainer campaign drafts, platform-specific posts and covers, recording
scripts, launch schedules, growth targets, channel analytics, and unpublished
raw user feedback under `.local/`. This directory is ignored by Git and must
never be copied into `docs/`, release packages, or published artifacts.

Public demos explain how the product works. They must not link to maintainer-only
campaign material. Publish user examples or feedback only with permission and
appropriate redaction. See CONTRIBUTING.md for the same content boundary.
